# 실제 성과와 개선

CSV·Excel·JSON·통계 화면·수동 표를 받는다. 파일명, 집계 단위, 측정 시작·종료일, 게시일, 수정일, 조회수·유입 지표의 의미를 먼저 확인한다. 숫자가 흐릿하거나 지표 정의가 없으면 확인을 요청한다.

1. 게시물별 중복·누락을 확인한다. 미제공을 0으로 바꾸지 않는다. 블로그 전체 유입 검색어를 특정 글의 유입으로 배분하지 않는다.
2. 게시 후 7·14·30일 등 확보된 동일 기간을 비교한다. 누적 조회수만 있으면 과거 구간 수치를 복원하지 않는다. 스냅샷 차이는 동일 정의·정상 집계인 경우에만 해당 구간 증가량으로 계산한다.
3. 표본 수와 함께 평균·중앙값을 보고한다. 기간·경과일이 다른 그룹은 별도로 표시한다. 비중은 분모가 실제 제공된 경우에만 계산한다.
4. 유입 검색어와 원래 의도를 비교하고 누락 정보·제목 불일치·가격 갱신 등 수정안을 만든다.
5. 수정 전후 같은 길이의 기간을 비교한다. 계절성·외부 유입·게시물 나이를 고려하고 인과관계를 단정하지 않는다. 이전 값이 0이면 증가율 대신 절대 차이를 제시한다.

노출수·클릭수·구매수가 없으면 CTR·전환율을 만들지 않는다. 조회수는 방문자 수와 같다고 가정하지 않는다. 비공식 통계 API를 기본 의존성으로 삼지 않는다.

출력: 게시물 / 기간·경과일 / 지표·실제 값 / 유입 근거 / 개선안 / 검증 가설 / 다음 측정일. 이전 전략과 변경 내용을 함께 남긴다. 통계 정의는 [게시글 통계](https://help.naver.com/service/5593/contents/15314)와 [유입 분석](https://help.naver.com/service/5593/contents/15330) 본문 또는 사용자의 실제 화면에서 확인한다. 두 문서는 2026-10-10 본문을 확인하지 못했으므로 여기서 세부 기능의 근거로 사용하지 않았다.
