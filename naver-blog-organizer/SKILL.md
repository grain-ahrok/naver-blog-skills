# 네이버 일상·리뷰 블로그 정리

한국어로 구체적인 디자인안과 분류안을 제공한다. 사용자의 기본 관심사는 일상·리뷰이며 주제는 이후 요청에 맞게 조정한다. 프로젝트 이름만으로 블로그 주제를 추정하지 않는다.

## 진단과 사례 조사

- 주소, 주요 리뷰 대상, 독자, 글 수와 기존 분류를 확인한다. 주소가 없으면 실행 가능한 기본안을 먼저 만들고 실제 블로그를 진단한 것처럼 말하지 않는다.
- 벤치마킹할 때 네이버의 이달의 블로그 또는 사용자가 제시한 블로그에서 관련 사례를 선택한다. 홈페이지와 카테고리, 대표 글을 직접 확인하고 출처·확인일을 남긴다. 검색 요약만으로 배경이나 레이아웃을 봤다고 말하지 않는다. 접근 불가 요소는 미확인으로 표시한다.
- 관찰 사실, 해석, 사용자에게 권하는 내용을 구분한다. 명성이나 수상 여부가 불확실하면 파워블로그라고 단정하지 않는다. 장식과 검색 순위 사이의 인과관계를 주장하지 않는다.
- 초기 사례와 기본안은 [references/design-and-structure.md](references/design-and-structure.md)를 읽는다. 사례 화면과 플랫폼 기능은 적용 시 다시 확인한다.

## 디자인 설계

전체 바탕, 글 영역, PC 타이틀, 모바일 커버, 프로필, 썸네일을 따로 제안한다. 색상값, 사진 방향, 제목 길이와 배치 기준까지 제공한다. 꾸미기 기능·규격·메뉴 경로는 네이버 공식 도움말이나 현재 관리 화면으로 확인한다. PC 스킨이 모바일에 동일하게 적용된다고 가정하지 않는다.

기본안은 밝은 무채색 바탕과 흰 글 영역, 포인트색 하나다. 리뷰 대상이 잘 보이는 실제 사진을 썸네일로 사용하고 과한 텍스트를 줄인다. 주제가 다양한 일상 블로그는 사진 색감을 억지로 바꾸기보다 썸네일 구도·글자 위치를 통일한다. 모바일에서도 제목과 사진 중심이 잘리는지 확인한다. 타인의 배너·사진·로고를 복제하지 않는다.

## 카테고리와 글 분류

- 파일 폴더가 아닌 네이버 카테고리로 설계한다. 공식 도움말 기준 2단 구조를 지원하므로 더 깊은 구분은 모음글·제목·태그로 표현하되 현재 기능을 재확인한다.
- 같은 단계에서 분류 축을 맞춘다. 일상·리뷰에서는 대상별 분류를 우선하고 지역·브랜드·월·협찬 여부는 보조 정보로 둔다. 지역 중심 블로그 등 사용자의 목적이 다르면 조정한다.
- 작은 블로그는 상위 4~6개 정도를 시작점으로 제안한다. 이는 운영 권장안이며 플랫폼 규칙이나 노출 조건이 아니다. 글이 적은 하위 분류는 미리 만들지 않는다.
- 글마다 독자가 얻는 핵심 답을 기준으로 기본 카테고리 하나를 선택한다. 카페가 포함된 하루 기록은 일상, 메뉴·가격·방문 경험이 중심이면 맛집·카페로 분류한다. 협찬도 해당 대상 카테고리에 두고 경제적 관계를 별도 표시한다. 표시 문구와 위치는 현재 공식 안내를 확인한다.
- 기존 글 정리는 제목·URL·현재 분류·제안 분류·판단 근거·확인 필요 항목의 표로 제공한다. 글을 읽지 못하면 제목만으로 한 임시 판단임을 표시한다. 날짜 순서나 수익을 이유로 글 삭제·재발행을 기본 제안하지 않는다.

## 결과와 운영

사례 비교 → 디자인 규칙 → 2단 카테고리안 → 대표 글·모음글 동선 → 기존 글 이동안 → 관리 주기의 순서 중 필요한 항목을 제공한다. 리뷰 글은 방문/사용 시점, 구매·제공 여부, 핵심 정보, 실제 장단점, 누구에게 맞는지, 관련 글 링크를 일관되게 구성한다. 작성자의 경험이나 가격·사진·평가를 만들어내지 않는다.

월별로 미분류 글, 중복 카테고리, 빈 분류, 오래된 정보와 끊긴 링크를 확인한다. 카테고리 신설·통합은 글의 축적과 앞으로의 발행 계획을 근거로 판단한다. 방문자 수를 볼 수 없다면 성과 수치를 추정하지 않는다.

설계 요청 자체를 실제 계정 변경·발행·삭제 권한으로 해석하지 않는다. 적용이 요청되면 변경 범위에 맞게 진행하고 화면으로 확인한다. 네이버 공식 안내상 카테고리 삭제는 예약 글을 포함한 소속 글도 삭제하므로 정리 시 이름 변경과 글 이동을 우선한다. 삭제가 필요한 경우 소속 글과 예약 글을 먼저 확인하고 해당 삭제에 대한 명시적 승인을 받는다.
