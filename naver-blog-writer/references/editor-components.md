# 편집 구성안 규격

게시용 본문과 편집 구성안을 분리한다. 구성안은 본문 순서와 내용을 그대로 담고 다음 표식을 삽입한다. B01 같은 블록 ID는 고유하며 수정 후에도 기존 ID를 재사용하거나 번호를 밀지 않는다. 삭제된 블록을 참조하는 사진 표는 함께 고친다.

```text
[블록:B01 | 소제목] 메뉴와 가격
본문 문단...
[블록:B02 | 사진:P03,P04 | 콜라주]
[블록:B03 | 인용구] 확인된 경험의 한 줄 요약
[블록:B04 | 장소] 확인한 장소명 | 확인한 플레이스 URL
[블록:B05 | 구분선]
[블록:B06 | 표]
항목 | 확인 정보
[블록:B07 | 링크카드] 확인한 URL
[블록:B08 | 스티커 | 목적:마무리인사 | 선택:기본·무료·보유항목 | 미지원:생략]
```

표식은 내부 편집 지시이며 공개 본문에는 남기지 않는다. 사진 ID는 사진 표의 파일과 연결한다. 장소는 실제 지점·주소·플레이스가 일치할 때만 첨부하고 비슷한 이름의 다른 지점을 선택하지 않는다. 장소 정보가 없으면 확인 필요로 남긴다.

구분선·인용구·스티커의 위치·역할은 [시각적 구성 지침](visual-rhythm.md)을 따른다. 표식에는 선택적으로 `스타일`, `역할`, `목적`, `미지원` 조건을 덧붙인다. 인용구의 역할은 작성자 요약·소제목 서식·실제 외부 인용을 구분한다. 스티커는 현재 선택 가능한 항목을 확인한 경우에만 구체적으로 지정한다.

사진 레이아웃은 `개별 / 콜라주 / 슬라이드`로 표시한다. 정보·메뉴판처럼 크게 읽어야 하는 사진은 개별, 함께 비교할 장면은 콜라주, 연속 장면은 슬라이드를 시작안으로 삼는다. 콜라주의 작은 글씨와 슬라이드 안에 숨는 핵심 정보를 미리보기에서 점검한다. 묶음은 정보 단위이며 항상 콜라주라는 뜻이 아니다.

실제 화면에서 지원되는 컴포넌트만 사용한다. 표·링크 카드 등이 없으면 일반 문단·목록·텍스트 링크로 대체하고 차이를 기록한다. 확인되지 않은 기능을 구현했다고 하지 않는다.

[공식 그룹 사진 안내](https://help.naver.com/service/5593/contents/15528?lang=ko&osType=PC)는 세 사진 형태를 설명한다(2026-10-10 본문 확인, 게시·수정일 미표시). 다른 컴포넌트의 현재 지원 여부는 실행 화면에서 확인한다.
## 내돈내산 기능 연결

직접 결제가 확인된 원고에는 네이버의 내돈내산 첨부 기능을 검토하도록 구성안에 적는다. 일반 직접 결제 문구와 네이버가 이용내역을 연결하는 기능을 구분한다. 직접 결제만으로 기능 이용 자격을 확정하지 않는다. 지원되는 스마트스토어 구매·네이버예약 등의 해당 이용내역이 조회되고 경제적 대가·협찬·수익형 요소가 없는지 확인해야 한다. 적용 여부와 남은 확인 사항을 publisher에 인계한다. 영수증·거래 상세의 개인정보를 본문·공개 저장소에 넣지 않는다.
