# Naver Blog Skills

네이버 일상·리뷰 블로그를 **디자인·정리 → 조사 → 원고 → 게시** 순서로 도와주는 한국어 Agent Skills 모음입니다. Claude Code와 Codex에서 사용할 수 있습니다.

> **한눈에 보기**
>
> 1. 스킬 폴더 4개를 `~/.claude/skills/`(Codex는 `~/.agents/skills/`)에 복사합니다.
> 2. 내 작업 폴더에 사진과 방문 메모를 넣고 `/naver-blog-writer 이 메모랑 사진으로 리뷰 써줘`라고 요청합니다.
> 3. `/naver-blog-publisher`에 대상 블로그와 목표(임시저장·발행)를 알려줍니다. 브라우저를 사용할 수 있으면 직접 게시 작업을 진행하고 필요한 조건만 확인받습니다.
>
> 실제로 겪지 않은 경험은 쓰지 않고 사진 속 개인정보는 네이버 편집기에서 필요한 최소 부분만 가립니다. 로컬 원본은 보존합니다. 게시 준비 요청은 검수용 임시저장을 기본으로 하며, 승인된 발행 요청은 실제 지침·권한 조건을 확인해 진행합니다.

## 어떤 스킬을 쓰나요?

| 이럴 때 | 스킬 | 받는 결과물 |
| --- | --- | --- |
| 배경·홈·카테고리와 기존 글 분류를 정리하고 싶다 | `naver-blog-organizer` | 사례 비교, 디자인 규칙, 카테고리안, 글 이동안과 관리 기준 |
| 어떤 키워드로, 어떤 내용을 써야 할지 모르겠다 | `naver-blog-strategist` | 키워드 후보, 독자 질문, 제목 3개, 글쓰기용 전달 메모 |
| 이미 쓴 글의 조회수를 보고 개선하고 싶다 | `naver-blog-strategist` | 성과 보고서, 수정 제안, 다음 측정일 |
| 메모와 사진으로 원고를 받고 싶다 | `naver-blog-writer` | 게시용 본문, 편집 구성안, 사진 배치표, 최소 가림 계획·검수 결과 |
| 원고를 네이버에 저장하거나 게시하고 싶다 | `naver-blog-publisher` | 브라우저에서 직접 입력·첨부·저장·게시 및 결과 검증, 필요 시 수동 안내 |

네 스킬은 각각 따로 써도 되고 순서대로 이어서 써도 됩니다. `publisher`는 안전을 위해 **직접 호출할 때만** 실행됩니다.

## 1. 설치 (명령 한 줄)

이 저장소 폴더에서 터미널을 열고 아래 한 줄을 붙여넣으세요. 스킬 폴더 4개만 복사됩니다.

**Windows (PowerShell)**

```powershell
mkdir -Force "$HOME\.claude\skills" > $null; cp -r -Force naver-blog-* "$HOME\.claude\skills\"
```

**macOS / Linux**

```bash
mkdir -p ~/.claude/skills && cp -R naver-blog-* ~/.claude/skills/
```

> 터미널이 익숙하지 않다면 이 폴더에서 Claude Code를 열고 **"이 폴더의 naver-blog 스킬 4개를 개인 스킬로 설치해줘"** 라고 요청해도 됩니다.

| 도구 | 개인 설치(모든 프로젝트) | 프로젝트 설치(이 폴더만) | 호출 |
| --- | --- | --- | --- |
| Claude Code | `~/.claude/skills/` | `.claude/skills/` | `/naver-blog-writer` |
| Codex | `~/.agents/skills/` | `.agents/skills/` | `$naver-blog-writer` |

Codex를 쓴다면 위 명령의 `.claude`를 `.agents`로 바꾸세요. 설치한 뒤에는 **새 세션을 열고** 스킬 목록에 4개가 보이는지 확인합니다(Claude Code는 `/`를 입력하면 목록이 보이고, Codex는 `/skills`). 공식 안내: [Claude Code](https://code.claude.com/docs/en/skills) · [Codex](https://learn.chatgpt.com/docs/build-skills)

## 2. 처음 한 번 해 둘 세팅

### 꼭 필요한 것

- [ ] **작업 폴더 만들기**: 원고와 사진은 스킬 폴더가 아니라 별도 작업 폴더에 둡니다. 아래 구조를 만들고 **이 폴더에서** Claude Code나 Codex를 실행하세요.

  ```text
  내-블로그-작업/
  ├─ photos/     ← 원본 사진(스킬이 덮어쓰거나 지우지 않음)
  ├─ data/       ← 통계·키워드 CSV 등 받은 자료
  ├─ reports/    ← 전략·성과 보고서
  ├─ drafts/     ← 원고
  └─ outputs/    ← 게시 작업표, redacted/(가림 처리된 사진 사본)
  ```

- [ ] **이 작업 폴더를 git으로 관리한다면** 저장소의 [.gitignore](.gitignore)를 작업 폴더에도 복사합니다. 이미 커밋된 파일은 `.gitignore`로 숨겨지지 않습니다.
- [ ] **아이폰 사진(HEIC)은 JPG로 변환**: 에이전트가 HEIC 파일을 열어 내용을 확인하지 못할 수 있습니다. 사진 설정에서 "호환성 우선"을 고르거나 미리 JPG로 바꿔 두세요.
- [ ] **네이버 블로그 카테고리 정하기**: `naver-blog-organizer`로 구조를 설계하고 네이버에서 적용합니다. 계정 변경은 적용 요청 범위에서 진행하며, 게시 스킬은 준비된 카테고리를 선택합니다.

### 있으면 좋은 것

| 기능 | 준비할 것 | 없으면 |
| --- | --- | --- |
| 사진 속 얼굴·번호 가림 | 네이버 글쓰기 사진 편집기 우선. 미지원 방식은 사용자 선택에 따라 별도 도구 사용 | 필요한 최소 영역을 기록하고, 검수 전에는 공개 발행하지 않습니다 |
| 위치정보(EXIF) 검사·제거, 선택한 로컬 가림 | Python + Pillow (`pip install pillow`), 선택으로 [ExifTool](https://exiftool.org/) | 메타데이터 미확인 상태를 알리고 해당 사진의 전송 여부를 확인합니다 |
| 웹 조사(공식 문서, 검색 화면) | 에이전트의 웹 검색·웹 읽기 도구 허용 | 직접 준 자료와 캡처 화면만 분석합니다 |
| 검색어 추이(데이터랩) | [네이버 개발자센터](https://developers.naver.com/)에서 애플리케이션 등록 후 환경 변수 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` 설정 | 수요를 "미확인"으로 표시합니다 |
| 월간 검색수 | 네이버 검색광고 계정의 키워드 도구에서 CSV를 내려받아 `data/`에 넣기 | 수요를 "미확인"으로 표시합니다 |
| 성과 분석 | 블로그 관리 → 통계 화면 캡처 또는 내보낸 파일을 `data/`에 넣기 | 분석할 수 없습니다 |
| 문체 맞추기 | 닮고 싶은 블로그 글 URL 1~5개 | 기본 문체(차분하고 친근한 해요체)로 씁니다 |

환경 변수 설정 예시 (API 키는 채팅에 붙여넣지 마세요):

```powershell
# Windows: 한 번 설정한 뒤 터미널을 다시 열어야 적용됩니다
setx NAVER_CLIENT_ID "발급받은-ID"
setx NAVER_CLIENT_SECRET "발급받은-Secret"
```

```bash
# macOS / Linux: ~/.zshrc 또는 ~/.bashrc에 추가
export NAVER_CLIENT_ID="발급받은-ID"
export NAVER_CLIENT_SECRET="발급받은-Secret"
```

## 3. 이렇게 요청하세요

Claude Code 기준입니다. Codex는 `/` 대신 `$`를 붙입니다.

**처음부터 끝까지**

```text
/naver-blog-strategist 연남동 작업 카페 리뷰를 쓰려고 해. 메모는 data/visit.txt야.
/naver-blog-writer 위 전략이랑 photos/ 사진으로 원고 써줘. 이모지 없이 해요체로.
/naver-blog-publisher drafts/ 최신 원고로 게시 준비해줘. 공개 범위는 전체공개.
```

**원고만 빠르게**

```text
/naver-blog-writer 어제 간 국밥집 후기. 2인 2만 4천 원, 대기 20분, 국물이 좀 짰음. 사진은 photos/gukbap/ 폴더.
```

**협찬 글**

```text
/naver-blog-writer ○○카페에서 음료 2잔을 무상 제공받았어. 원고료는 없음. 사진은 photos/cafe/.
```

**기존 글 개선**

```text
/naver-blog-strategist data/stats.csv 보고 지난달 글 중에 뭘 고치면 좋을지 알려줘.
```

**말투 맞추기**

```text
/naver-blog-writer 이 글들 말투 분석해서 그대로 맞춰줘: (참고 URL 1~3개)
```

> 💡 방문일, 가격, 협찬 여부, 직접 결제했는지를 처음부터 알려주면 질문을 덜 받습니다.

## 4. 결과물 읽는 법

**원고 상태**

| 표시 | 의미 | 할 일 |
| --- | --- | --- |
| 초안 | 구성은 잡혔지만 다듬는 중 | 피드백 주기 |
| 확인 필요 | 가격, 사진 가림, 협찬 정보 등 확인할 것이 남음 | "게시 전 확인" 목록 해결 |
| 게시 준비 완료 | 올려도 되는 상태(아직 게시된 것은 아님) | publisher 호출 또는 직접 게시 |

**사진 검수 상태**: 공개 발행에는 `가림 불필요·검수 완료`와 `가림 완료·검수 완료` 사진만 사용합니다. 네이버에서 가릴 미검수 사진은 사용자가 편집용 전송을 승인했을 때만 작성 화면에 첨부하고, 편집·검수 후 상태를 갱신합니다. `제외` 사진은 첨부하지 않습니다. 얼굴이 식별되는 최소 부분만 가리며 얼굴 없는 부분·몸·주변 공간을 일괄 가리지 않습니다.

**편집 구성안의 `[블록:B02 | 사진:P03,P04 | 콜라주]`**: 네이버 편집기에서 이 위치에 사진 P03, P04를 콜라주로 넣으라는 표시입니다. 공개 본문에는 들어가지 않습니다.

**구분선·인용구·스티커**: `naver-blog-writer`가 참고 글 조사와 사용 여부·위치·스타일을 결정해 편집 구성안을 만듭니다. `publisher`는 그 구성안을 편집기에 적용하고 결과를 확인합니다. 사용 기준과 조사 한계는 writer의 [시각적 구성 지침](naver-blog-writer/references/visual-rhythm.md)에 있습니다.

**사진 배치**: 제공된 사진을 기본적으로 모두 활용합니다. 비슷한 사진은 네이버 콜라주로 2~3장씩 가로 배치를 고려하고, 모바일에서 글자가 작아지면 개별 배치합니다. 사진 제외는 이유를 설명하고 확인받습니다.

**내돈내산 기능**: 직접 결제 글은 네이버에서 지원되는 해당 구매·예약 내역이 조회되는지 확인하고 조건을 충족하면 연결합니다. 일반 직접 결제 문구와 별개이며, 이용안내 동의는 필요한 사용자 확인을 거칩니다.

**게시 실행**: publisher는 브라우저에서 확정 원고·검수 사진·편집 구성안을 직접 적용하고 실제 저장·게시 상태를 확인합니다. 복사용 본문은 백업으로 보관하며, 브라우저 기능 부재·해당 작업 제한·수동 작업 선택 시에는 단계별 체크리스트도 제공합니다.

**게시 결과**: `로컬 준비 완료`는 내 컴퓨터에 자료만 준비됐다는 뜻입니다. `임시저장 확인`과 `발행 확인`은 실제 네이버 상태를 확인한 결과이며 서로 구분합니다.

**브라우저 접속**: 업로드 준비를 요청하면 지정한 블로그를 브라우저에 띄우고 로그인 상태와 글쓰기 화면을 확인합니다. 주소가 없을 때만 어느 블로그인지 묻고, 이미 알려준 주소는 다시 묻지 않습니다. 로그인은 직접 진행하며, 본문 입력·사진 전송은 별도로 허용 범위를 확인합니다.

## 5. 자주 묻는 질문

**Q. 브라우저가 연결되면 직접 올려주나요?**
직접 실행을 우선합니다. 대상 블로그·로그인·도구 기능·확정 원고와 사진을 확인하고, 필요한 지침·권한 조건이 충족되면 입력·저장·승인된 발행까지 진행합니다. [네이버 이용약관](https://policy.naver.com/policy/service.html)에는 사전 허락 없는 자동 로그인·게시·자료 삽입 제한이 있으므로, 실제 방식에 해당 조건이 적용되면 출처와 이유를 설명해 필요한 확인을 받습니다. 사용자 승인이 플랫폼 제한을 해제하는 것은 아닙니다. 최종 발행 승인만 남았다면 허용된 임시저장과 미리보기를 먼저 완성하며, 수동 안내는 직접 실행이 어려운 단계의 대안입니다.

**Q. "상위 노출되는 법"도 알려주나요?**
검색 순위를 보장하거나 사진 수, 글자 수 같은 공식을 만들어내지 않습니다. 실제 데이터와 검색 화면을 근거로 독자가 궁금해할 질문에 답하는 글을 설계합니다.

**Q. 원본 사진이 바뀌나요?**
아니요. 기본은 네이버 사진 편집기의 게시용 사진에 적용하며 로컬 원본은 보존합니다. 별도 로컬 편집을 선택하면 `outputs/redacted/` 사본에 적용합니다. 현재 편집기에 요청한 블러 기능이 없으면 모자이크 등 지원 기능과 차이를 설명하고 선택을 받습니다.

**Q. 안 가본 곳 후기도 써 주나요?**
아니요. 경험이 없으면 정보형 글 구성을 제안하거나 필요한 정보를 질문합니다.

## 지키는 원칙

- 경험, 맛, 가격, 검색량, 성과를 지어내지 않습니다. 직접 결제한 것이 확인되지 않으면 `내돈내산`으로 표시하지 않습니다.
- 협찬을 받았다면 제공한 곳과 받은 대가를 제목이나 본문 첫 부분에 텍스트로 밝힙니다.
- 병원·시술, 건강식품, 화장품, 부정적 리뷰는 관련 법규를 기준으로 표현을 검수합니다(법률 자문은 아님).
- 임시저장도 외부로 보내는 것이므로, 올리기 전에 개인정보와 업로드 범위를 확인합니다.
- 비밀번호, 쿠키, API 키는 어떤 파일에도 기록하지 않습니다.
