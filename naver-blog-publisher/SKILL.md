# 네이버 블로그 게시

## 호출과 정책 조건

사용자의 명시적 호출로만 실행한다. Claude Code에서는 `/naver-blog-publisher`, Codex에서는 `$naver-blog-publisher`를 사용한다. 다른 스킬이 자동 호출하거나 이 제한을 피하려고 게시 단계를 대신 수행하지 않는다. Claude용 frontmatter와 Codex용 `agents/openai.yaml`은 각각 해당 제품의 호출 제어다.

기본 흐름은 **브라우저에서 직접 게시 작업**이다. 연결 가능한 브라우저와 실제 입력·사진 첨부 기능을 먼저 확인하고 사용자 요청 범위에서 수행한다. “게시 준비”만 요청하거나 최종 제출 승인이 미확정이면 검수용 임시저장까지 진행한 뒤 실제 미리보기와 설정을 보여준다. 명시적으로 승인된 발행·예약·수정은 해당 단계까지 진행한다. 복사용 본문은 백업 자료이며, 브라우저를 사용할 수 없거나 해당 단계가 제한되거나 사용자가 수동 작업을 선택한 경우에 [수동 게시 안내](templates/manual-guide.md)를 제공한다. 로컬 파일 생성은 네이버 임시저장 완료가 아니다.

[네이버 이용약관](https://policy.naver.com/policy/service.html)에는 사전 허락 없는 자동 로그인·게시·자료 삽입 제한이 있다(2026-10-11 확인, 시행 2026-10-01). 실제 사용할 수단·계정·작업에 적용되는 현재 공식 문서와 화면 안내를 확인한다. 공식 문구, 해당 작업에 대한 적용 해석, 도구 권한, 사용자 작업 승인을 구분한다. 브라우저 연결이 플랫폼 허락을 증명하거나 사용자 승인이 명시적 플랫폼 제한을 해제하는 것은 아니다. 임시저장·사진 첨부도 외부 전송이다.

사용자에게 모든 작업의 사전 허락 증빙을 일괄 요구하지 않는다. 확인이 필요한 조건이 실제로 생기면 대상 블로그·원고 버전·실행할 동작·완료한 준비를 먼저 특정하고, 관련 출처·조항 또는 화면과 필요한 이유를 짧게 제시해 질문한다. 예: “현재 확인한 조항은 이 자동 입력 방식에 사전 허락을 요구하는 것으로 보입니다. 이 수단에 적용되는 네이버 안내를 받은 적이 있나요?” 또는 “이 미리보기의 원고와 사진을 지정한 공개 범위로 발행할까요?” 기존 답변·근거·구체적 작업 승인은 재사용한다. 막연한 위험이나 자체 권장안 때문에 같은 승인을 반복해서 받지 않는다. 답변 대기나 침묵을 승인으로 간주하지 않는다.

보류 범위는 확인이 필요한 동작에 한정한다. 최종 발행만 확인이 필요하면 허용된 입력·사진 첨부·임시저장을 먼저 완성한다. 자동 입력·전송 자체에 적용되는 제한이나 필수 허락이 미해결이면 해당 동작 이전에 질문하고 로컬 원고·사진 준비와 읽기 전용 화면 확인을 계속한다. 로그인·인증은 사용자에게 직접 진행하도록 요청한다. 명시적 제한을 확인했거나 사용자가 필요한 근거를 제공할 수 없다고 답하면 그 단계의 허용되는 대안·수동 안내를 완성한다. 실제 제한과 기술적 기능 부재를 혼동하지 않는다.

반복 자동 발행 스케줄러를 만들지 않는다. 예약 요청은 네이버 기본 예약 기능을 사용하고 요청 시각·시간대를 확인한다. 직접 예약 등록에도 위 조건을 적용한다. CAPTCHA·접근 제한을 우회하지 않는다.

## 준비와 조건부 실행

1. 대화·기존 작업표에서 대상 블로그 주소와 요청 범위를 확인한다. 주소가 없거나 후보가 여러 개이면 “어느 네이버 블로그에 올릴까요? 블로그 주소를 알려주세요.”라고 묻는다. 이미 지정한 주소는 재사용하며 같은 질문을 반복하지 않는다. 다른 서비스 계정명이나 네이버 표시 이름으로 블로그 주소를 추정하지 않는다. [게시 작업표](templates/publish-job.md)로 원고 ID·버전, 대상 블로그, 사진, 설정과 요청 범위를 정리한다. 사진 없는 글도 가능하다. 미지정 공개 범위를 추정하지 않고 원격 제출 전 확정한다.
2. 제목·협찬 표시·경험 근거와 본문 개인정보를 검수한다. 공개 발행에는 실제 검수 사진만 연결한다. 기본 사진 가림은 네이버 사진 편집기를 사용하며, 사용자가 해당 사진의 네이버 편집용 전송을 승인한 경우에만 미가림 파일을 작성 화면에 첨부해 편집한다. 이 파일은 확인 필요 상태로 유지하고 실제 편집·확대 검수 후 완료로 갱신한다. `제외` 파일은 전송하지 않는다. 메타데이터 미확인은 해당 파일의 사용자 예외 허용이 있을 때만 처리한다. 사용자 허용은 플랫폼 허락과 별개다.
3. 깨끗한 게시 본문, 블록 ID를 유지한 편집 구성안, 사진 표, 설정표를 사용자 작업 폴더에 저장한다. 내부 표시·비공개 경로가 공개 본문에 남지 않게 한다. 세부 변환·검수는 [편집기 지침](references/editor-and-verification.md)을 따른다. 백업 본문을 만들되 브라우저 실행이 가능한 작업을 복사·붙여넣기 안내만으로 끝내지 않는다.
4. 접속·업로드 준비를 요청받으면 [브라우저 접속 절차](references/editor-and-verification.md#대상-블로그와-브라우저-접속)에 따라 지정한 브라우저·탭을 사용하거나 대상 블로그를 새 탭으로 연다. 준비 화면을 사용자에게 보이게 하고 로그인 상태·블로그 주소·글쓰기 화면을 확인한다. 자동 입력 허락이 미확인이라는 이유만으로 읽기 전용 접속을 생략하지 않는다. 원격 자동 실행 요청이 있으면 플랫폼 허락·사용자 요청·도구 권한을 각각 확인한다. 허락 범위 미확인은 위 확인 질문과 병행 준비 흐름으로 처리한다. 도구가 없으면 실제로 부족한 기능을 설명하고 수행 가능한 준비 및 수동 안내를 완성한다. 자격증명은 기록하지 않는다.
5. 허용된 원격 작업에서는 현재 화면의 기능으로 확정 제목·본문·검수 사진과 구성안을 직접 적용한다. 기존 작성 중인 글을 덮어쓰지 않는다. 사진 개수·순서·레이아웃, 장소 일치, 캡션·가림·협찬 표시를 확인하고 요청된 설정만 변경한다. 실제 임시저장 상태·미리보기에서 검수한다. 최종 제출 승인이 필요한 경우 이 구체적인 결과와 설정을 보여주고 확인을 요청한다.
6. 사용자 승인과 필요한 권한·지침 조건이 충족되면 요청된 발행·예약·수정을 직접 실행한다. 도구가 최종 동작을 사용자에게 넘기도록 요구하는 경우에만 해당 동작을 인계한다. 제출 후 실제 URL·상태·표시 내용을 검증한다. 사용자 완료 통보만 있으면 통보 기반임을 밝히고 실제 확인 없이 완료를 주장하지 않는다.

## 기록과 복구

작업 ID·버전·현재 단계·확인한 저장 정보·실제 URL을 사용자 작업 폴더의 비공개 `outputs/`에 남긴다. 스킬 폴더에는 결과나 자격증명을 저장하지 않는다. 같은 작업 재개 시 실제 초안·글과 기록을 대조하며 제목만으로 동일 글이라고 단정하지 않는다.

결과는 `로컬 준비 완료 / 근거 확인 대기 / 사용자 검수 대기 / 임시저장 확인 / 발행 확인 / 예약 등록 확인 / 수정 확인 / 결과 불명확 / 차단`으로 구분한다. 대기 상태에는 완료한 준비, 보류한 동작, 질문과 필요한 자료를 기록한다. 발행 확인에는 직접 실행·사용자 실행 여부를 함께 남긴다. 단순 미확인을 차단이나 기술적 불가능으로 보고하지 않는다. 예약 등록은 발행 완료가 아니다. 최종 제출 후 타임아웃이면 다시 제출하지 말고 실제 상태를 먼저 확인한다. 확인할 수 없으면 결과 불명확으로 멈춘다. 비최종 입력 실패는 상태 관찰 후 해당 단계만 최대 2회 재시도한다. 무단 원고 변경·삭제로 복구하지 않는다.
