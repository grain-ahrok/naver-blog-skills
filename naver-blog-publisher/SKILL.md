# 네이버 블로그 게시 준비

## 호출과 정책 조건

사용자의 명시적 호출로만 실행한다. Claude Code에서는 `/naver-blog-publisher`, Codex에서는 `$naver-blog-publisher`를 사용한다. 다른 스킬이 자동 호출하거나 이 제한을 피하려고 게시 단계를 대신 수행하지 않는다. Claude용 frontmatter와 Codex용 `agents/openai.yaml`은 각각 해당 제품의 호출 제어다.

기본 모드는 **임시저장 준비**다. 로컬에 확정 원고·사진·설정표를 만들고 사람이 편집기에 입력해 임시저장하도록 안내한다. 최종 발행은 사람이 미리보기를 확인하고 누르는 방식을 권장한다. 로컬 파일 생성은 네이버 임시저장 완료가 아니다.

[네이버 이용약관](https://policy.naver.com/policy/service.html)의 사전 허락 없는 자동 로그인·게시·자료 삽입 제한을 따른다(2026-10-10 확인, 시행 2026-10-01). 임시저장·사진 첨부도 자동 입력·외부 전송이다. 사용자 동의, 정상 브라우저, 낮은 빈도, 사람의 최종 클릭만으로 네이버의 허락을 대체하지 않는다. 자동 실행은 네이버가 해당 수단·계정·작업에 허락한 근거와 범위가 확인된 경우만 진행한다. 근거가 없으면 로컬 자료와 수동 안내로 끝낸다. 편집기 기능 안내를 자동화 허락으로 해석하지 않는다.

반복 자동 발행 스케줄러를 만들지 않는다. 예약 요청은 사람이 네이버 기본 예약 기능을 사용하도록 안내한다. 자동 예약 등록도 위 정책 조건이 충족된 범위에만 가능하다. CAPTCHA·접근 제한을 우회하지 않는다.

## 준비와 조건부 실행

1. [게시 작업표](templates/publish-job.md)로 원고 ID·버전, 대상 블로그, 사진, 설정과 요청 범위를 정리한다. 사진 없는 글도 가능하다. 미지정 공개 범위를 추정하지 않고 원격 제출 전 확정한다.
2. 제목·협찬 표시·경험 근거와 본문 개인정보를 검수한다. 사진은 실제 검수 파일만 연결한다. `확인 필요 / 제외` 파일은 전송하지 않는다. 메타데이터 미확인은 해당 파일의 사용자 예외 허용이 있을 때만 처리한다. 사용자 허용은 플랫폼 허락과 별개다.
3. 깨끗한 게시 본문, 블록 ID를 유지한 편집 구성안, 사진 표, 설정표를 사용자 작업 폴더에 저장한다. 내부 표시·비공개 경로가 공개 본문에 남지 않게 한다. 세부 변환·검수는 [편집기 지침](references/editor-and-verification.md)을 따른다.
4. 원격 자동 실행 요청이 있으면 플랫폼 허락·사용자 요청·도구 권한을 각각 확인한다. 도구가 없거나 허락 범위를 확인할 수 없으면 수동 입력 안내로 인계한다. 실제 로그인 계정과 대상 블로그를 확인하며 다른 서비스 계정으로 추정하지 않는다. 자격증명은 기록하지 않는다.
5. 허용된 원격 작업에서는 현재 화면의 기능만 사용한다. 기존 작성 중인 글을 덮어쓰지 않는다. 사진 개수·순서·레이아웃, 장소 일치, 캡션·가림·협찬 표시를 확인한다. 요청된 설정만 변경한다. 기본은 임시저장까지이며 최종 발행 자동 실행은 기본 흐름에 포함하지 않는다.
6. 사람의 최종 발행 또는 예약 후 확인 가능한 실제 URL·화면을 검수한다. 사용자 완료 통보만 있으면 통보 기반임을 밝힌다. 실제 확인 없이 완료를 주장하지 않는다.

## 기록과 복구

작업 ID·버전·현재 단계·확인한 저장 정보·실제 URL을 사용자 작업 폴더의 비공개 `outputs/`에 남긴다. 스킬 폴더에는 결과나 자격증명을 저장하지 않는다. 같은 작업 재개 시 실제 초안·글과 기록을 대조하며 제목만으로 동일 글이라고 단정하지 않는다.

결과는 `로컬 임시저장 준비 완료 / 임시저장 확인 / 사람 발행 확인 / 예약 등록 확인 / 수정 확인 / 결과 불명확 / 차단`으로 구분한다. 예약 등록은 발행 완료가 아니다. 최종 제출 후 타임아웃이면 다시 제출하지 말고 실제 상태를 먼저 확인한다. 확인할 수 없으면 결과 불명확으로 멈춘다. 비최종 입력 실패는 상태 관찰 후 해당 단계만 최대 2회 재시도한다. 무단 원고 변경·삭제로 복구하지 않는다.
